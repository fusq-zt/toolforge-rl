# ToolForge-RL

基于 Qwen2.5-3B 的工具推理训练实验，研究如何在保持答题能力的同时减少多余的工具调用。

在 **2,619 道固定评测题**上，高效 GRPO 将平均工具调用次数降低 **21.88%**，准确率由 **70.98%** 变为 **70.94%**。

## 主要结果

![各模型的工具调用效率与准确率对比](reports/figures_readme/main_results_zh.png)

图中越靠左上越好。横轴为总调用次数除以答对题数；高效 GRPO 在这一指标上降低 **21.84%**。

两组模型使用相同的 SFT 初始化和训练设置，仅调整奖励中的效率项。

平均调用降幅的 95% 置信区间为 **[19.91%, 23.93%]**；准确率差异为 **−0.04 个百分点**，95% 置信区间为 **[−1.22, +1.18]**。

## 方法

### 数据来源与划分

从公开训练集抽取 2,000 道题，另合成 500 道检索计算题，共 **2,500 道原题**：

| 任务类型 | 数量 | 来源 |
|---|---:|---|
| 直接作答观察 | 500 | GSM8K |
| 数学推理 | 750 | GSM8K 375 道 + MATH 375 道 |
| 检索推理 | 750 | HotpotQA、2WikiMultihopQA 及其配套文档 |
| 检索后计算 | 500 | 合成实体、数值与文档，覆盖求和、差值、乘积和加权计算 |

去重后按原题 ID 划分为 **SFT 1,100 道、RL 候选 800 道、Dev 200 道、Internal Test 400 道**。最终评测为 Internal Test 400 道 + 公开 held-out 2,219 道。

详见[来源清单](data/manifests/source_manifest.json)、[划分清单](data/manifests/raw_prompt_manifest.json)与[构建脚本](scripts/build_raw_prompts.py)。

### 训练流程

1. **轨迹构建**：Tool-Star 对 1,100 道题各生成 3 条轨迹，经答案、协议与真实执行验证，选出 **1,076 条**；加入 **1,000 条公开参考**，得到 **2,076 条 SFT 样本**。公开参考仅作格式与长度筛选，未逐条重执行。
2. **监督微调**：对 **Qwen2.5-3B-Instruct** 进行 LoRA SFT，学习 Python 计算与 BM25 本地检索的多轮交互。
3. **RL 选题**：冻结 SFT 模型，对 800 道候选题各采样 4 次，保留正确性、调用次数或奖励有差异的 **432 道题**。
4. **策略训练**：每题在线采样 4 条轨迹，对比 **Vanilla GRPO** 与 **Efficient GRPO**；屏蔽工具返回文本的策略损失，使用冻结 SFT 参考策略提供 KL 约束。

高效版本仅对正确轨迹的额外调用扣分：

```text
R_efficient = R_base - 0.15 × max(0, C - C*)  （仅对正确轨迹）
```

`C` 为当前轨迹的执行调用数，`C*` 为同题组内正确轨迹的最少调用数；组内全错时效率惩罚为 0。

项目复用 [Tool-Star](https://github.com/RUC-NLPIR/Tool-Star) 的协议和公开资源，实现数据处理、工具执行、验证与训练流程。
